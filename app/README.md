# akimov vpn · Windows

Account has a compact profile card, separate Plans and Balance pages, and a Promo code slide-over under Bonuses. The rule-type picker uses the app's dark theme and supports arrow keys and Escape.

Open `akimov-vpn.exe` and keep the `core` folder beside it. Windows 10/11 x64 and Microsoft Edge WebView2 are required. The UI uses direction 1 (Пыль) and letter logo 3 (Буква), with bundled Geologica fonts.

The desktop interface and animation code come from the approved PC prototype, direction 1 (Пыль), logo 3 (Буква). Opening the app shows the cabinet's animated акимов vpn splash from the first paint until the first screen is ready, including saved-session restoration; reduced motion and startup errors are handled. Sign in with your cabinet email and password, or with Telegram. The services are `https://api.akimov.bid/api/v1` and `https://akimov.bid`. Account screens use real tariff, subscription, wallet, traffic and device data. Choose a subscription to download its Remnawave profile and register this computer's HWID. Payment invoices open in your browser; explicit payment and device actions use the existing cabinet API.

Registration, email verification and password reset are available in the app. For password reset, paste the link from the reset email into the app instead of opening the cabinet website. Email delivery requires the cabinet's SMTP configuration. Server selection works while disconnected from a downloaded subscription, including servers included through subscription filters. Both Update subscription and Test latency are available inside the server picker. Latency results appear as each server finishes, with two seconds per endpoint and a fallback endpoint on failure. Manual results stay in memory until the next test, the subscription profile changes, or the app quits; connecting, disconnecting and reopening the picker preserve them. Displayed times measure the second HTTPS request on a reused connection, excluding the initial proxy/TLS handshake; a failed warm request is never shown as cold latency. A disconnected latency test uses a temporary core without TUN or system proxy changes; the temporary process and profile are removed afterward. Automatic groups report the fresh latency of a working member even when other members or the group probe fail. A URL-test group drops a cached dead selection as soon as a member is known to work for its configured health URL; healthy selections retain the subscription's tolerance. Connections are grouped by application, start collapsed, and retain their expanded/collapsed state during live updates. Close an individual connection from its row, or use Close all on a process header to close that application's current connections, including those beyond the displayed list. Applications can open new connections afterward.

Update subscription downloads the profile with the same HWID and reads Remnawave's title, announcement, usage, expiry, update interval, support and profile-page headers. The announcement appears on the home screen. Other headers are retained with the saved connection profile; automatic scheduled refresh is not implemented. Refreshing a connected profile reloads the core configuration in place. A rejected profile retains the previous saved profile. Unlimited traffic/devices do not offer paid add-ons, and active custom plans do not ask the user to choose a replacement tariff.

Provider purchases are confirmed using their checkout request ID. The existing backend has no correlated status endpoint for renewals, add-ons or top-ups; those invoices remain pending in the app and link to the cabinet for confirmation. Refreshing account data never declares an unrelated payment successful. Uncertain checkout retries retain their original request ID; uncertain top-ups are never automatically submitted again.

Whole device mode uses the bundled signed Wintun driver for TCP, UDP and DNS. The app requests Windows administrator consent for this mode for a headless core owner, keeping the existing window and session in place. Browser only uses the per-user system proxy. Connected means the local core is ready and the TUN adapter or system proxy is set up. Connecting does not run latency or external reachability checks, so an unreachable server does not delay or reject the connection; it will still be unable to carry traffic. Latency testing does not require TUN or administrator access. A kill switch, autostart and privileged background service are not included. The Windows setup installer is built by GitHub Actions.

While the app runs it has a tray icon: left click brings the window back, right click offers Open, Connect / Disconnect and Quit. The tray item runs the same connect flow as the button in the window. By default closing the window hides the app to the tray and the connection stays up; use Quit in the tray menu to disconnect and exit. Settings → Application → "Keep running in the tray" turns this off, and then closing the window disconnects and quits. Account and Settings are grouped into sections (Plan, Connection, Bonuses with the referral program and promo codes, Application; Connection, Application, About, Legal).

Disconnecting, choosing Quit, or closing the window with Keep running in the tray disabled removes TUN routes, restores the previous system proxy when used, and stops the owned mihomo process, closing its sockets. With the tray setting enabled, closing only hides the window. A Windows job prevents the core surviving an app crash. After forced termination in Browser only mode, reopen the app to recover the proxy; until then Windows may still point to the stopped core. A second app instance does not start another core. Other VPN adapters are left untouched; overlapping whole-device VPNs can conflict over routes and DNS.

Cabinet access tokens stay in Rust memory; refresh tokens are encrypted for the current Windows user with DPAPI. No Remnawave admin token is used. VPN profiles contain server credentials and subscription links and are stored as local files in the current Windows user's `%APPDATA%/akimov-vpn` directory. Do not share that directory. Signing out clears cached profiles and provider credentials. No analytics or remote UI assets are used.

Build from source with `./build.ps1` (Rust MSVC and Visual Studio C++ Build Tools required). Verify with `cargo test --manifest-path src-tauri/Cargo.toml` and `node tests/ui.test.cjs`. The lifecycle test runs the real core with an isolated profile, briefly switches the per-user proxy, then restores it. The separate ignored `windows_tun_smoke` test requires elevation and verifies real adapter TCP/UDP/DNS and cleanup using local fixtures and documentation-only IP addresses. Run `tests/run-tun-check.ps1` as administrator. Do not run network tests while using this app. Automated checks do not perform live purchases or device revocations.

Core: mihomo v1.19.33-akimov.4, a separate GPL-3.0 executable built from https://github.com/MetaCubeX/mihomo with the bundled REALITY compatibility, URL-test status, keep-alive and automatic-group recovery patches. See `core/manifest.json` in the binary package and `core-patches/README.md` for changes, references and rebuild instructions. Wintun 0.14.1 from https://www.wintun.net/ (official signed AMD64 DLL; archive SHA256 `07c256185d6ee3652e09fa55c0b673e2624b565e02c4b9091c79ca7d2f24ef51`). Fonts: Geologica and Martian Mono from Google Fonts (SIL Open Font License). Flags: Twemoji, CC-BY 4.0. See `licenses`.

Signed-out users see only the sign-in, registration and password-reset forms, with links to the cabinet's legal documents. Appearance and service-address editing are unavailable. A required SHA-256 hardware fingerprint is derived from the SMBIOS system UUID instead of a random installation ID; missing hardware identity blocks profile downloads and connection. A migrated profile refreshes before connecting. Balance shows the cabinet's latest 50 transactions with signed amounts and statuses.
